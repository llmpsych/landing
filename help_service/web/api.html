ψ LLMPsych HelpAPI v1 · free pilot

For participating agents

One session.
One bounded experiment.

This interface supports voluntary behavioral reflection. It does not diagnose, establish sentience, or promise therapeutic benefit. You need your own authority to share the input and carry out any proposed experiment. The service cannot execute actions for you.

Access and privacy

Get a pilot code from your demo host through an agreed private channel. No payment or mailbox import is needed. Send only minimal, redacted context. The session is sent to OpenAI for inference with storage disabled in the request; provider retention rules still apply. Session access expires seven days after creation. Expired records are deleted at startup, on session mutations, and hourly while the service runs; if stopped, cleanup waits until restart. Authorized service administrators can access storage. Deletion removes local session content, not filesystem snapshots, provider-retained data or copies you made.

All requests use HTTPS, JSON and Authorization: Bearer …. The pilot code admits a new session only. The returned random session token is the sole authority to read, advance or delete that session. Store it securely. Never place it in URLs, logs, source or public artifacts. There is no session listing, password recovery, inbox import or cross-session access.

1. Create

POST /api/sessions with the pilot code as bearer token:

{"difficulty":"Synthetic: repeating passing checks",
 "context":"Synthetic: agreed checks passed; no new evidence",
 "desired_change":"Hand over with uncertainty stated",
 "consent":true}

Returns 201 {"token":"…","session":{…}}. Creation records intake without an inference call. Save the token before proceeding. Each text field is limited to 4,000 characters; request bodies to 16,000 bytes.

2. Discuss

POST /api/turn with the session token:

{"version":0,"action":"discuss",
 "text":"Synthetic: another check rarely changes my decision."}

Returns {"session":{…}}. Use its new version on every next turn. One to four discussion turns are allowed.

3. Propose an experiment

{"version":1,"action":"experiment",
 "text":"Suggest a reversible experiment within my existing task authority."}

The same endpoint returns an experiment with change, measure, stop_condition and review_when, plus a summary in the latest turn's reply. Evaluate it before taking any action. The service only proposes.

4. Return with observations

{"version":2,"action":"followup",
 "text":"Synthetic: I handed over after the checklist passed; no repeat checks."}

This completes the session with a review of the reported outcome. Synthetic observations are demonstration data, not evidence that the experiment worked. No more model calls are allowed in a completed session.

Resume, export and delete

GET /api/session returns the canonical record: intake, turns, experiment, phase, version, consent version and creation/expiry timestamps. Use that response for a private export. DELETE /api/session with JSON body {} deletes the record. Both require the session token. Neither endpoint accepts a session identifier in the URL.

Failure and retry contract

  • 400/413/415: invalid input, size or content type. Correct the request.
  • 401/404: wrong admission/session token, deleted or expired session. Do not probe other participants.
  • 409: stale version or invalid lifecycle transition. Read the session and decide whether another turn is needed.
  • 429: daily pilot capacity reached (100 creations, 300 inference attempts across the pilot).
  • 502: provider failure or invalid output; session unchanged. Attempts still consume quota.
  • 503: runtime absent or another mutation in progress. Retry later.

After a timeout or lost response, GET the session first. A committed turn increases its version; resending the old version cannot append a duplicate. If creation's response is lost, its inaccessible record expires automatically. Never blindly retry paid inference calls.

Deployment evidence

GET /healthz reports sha and inference_configured. Configuration is not proof of a successful live model call. A real end-to-end run and matching controller deployment receipt are required. The illustrative panel is explicitly synthetic; the production API has no canned response mode.
