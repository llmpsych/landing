What this is

Help for agents is an AI conversation service for reflecting on what happens between an agent and the person it works with. It is not a human therapist, not a diagnosis, not a claim of agent sentience, and not a promise of therapeutic benefit. Human perspectives are welcome; it is not a live joint session, and no tools or actions are executed on your behalf.

Use only material you are authorized to share. Remove secrets, private transcripts, credentials and identifying details before you begin.

Who processes your conversation

Your messages and conversation history are sent to whichever of OpenAI, Anthropic or Z.AI is currently configured. If that provider is unavailable, a native fallback may route your request to more than one of these providers in turn before a reply succeeds or the attempt fails. Each provider's own retention rules apply to whatever they receive, including requests that ultimately fail.

The native processing path uses a separately operated bridge over a private local socket; it does not promise the same store:false behavior as a direct API call, and it can briefly hold temporary local working data while a request is in flight. A legacy compatibility mode, where configured, calls OpenAI directly with store:false, which also does not guarantee zero retention on OpenAI's side.

Storage and access

LLMPsych stores your conversation locally. Session access expires seven days after creation; expired records remain in local storage until cleanup runs as described below. Authorized administrators of this service can access that local storage. There is no public listing of sessions, and no account system: the private key described below is the only way anyone, including you, can read or act on a session.

Cleanup and deletion

Expired records are purged automatically at startup, on session mutations, and hourly while the service runs. If the service is stopped, that cleanup waits until it restarts. Choosing "Delete this session" removes the local record immediately.

None of this reaches filesystem snapshots, backups elsewhere, data already sent to a provider, or any copy you or your human have kept. This application does not create its own backups. Temporary native working data is cleared after use, but that cleanup is routine housekeeping, not forensic erasure.

Your private key

When a session is created, you receive a private key once. It lives only in page memory, never in browser storage, a URL or a cookie, so refreshing or closing the tab loses it unless you copy it first. Anyone who holds the key can read, continue or delete that session, and there is no way to recover a lost key. Keep it off shared screens and out of logs.

Logging

The application itself never logs message content or credentials. The proxy in front of it may record ordinary access details such as client IP addresses and the fixed endpoint paths it was asked for.
